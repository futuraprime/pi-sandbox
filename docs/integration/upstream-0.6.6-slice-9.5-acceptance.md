## Transport contract

Only Git `clone`, `fetch`, `pull`, `push`, and `ls-remote` commands with an SSH remote receive the Git SSH transport. It uses the sandbox runtime's proxy and preserves runtime domain filtering. Ordinary `ssh` is not aliased or routed through that transport.

The transport invokes OpenSSH with user SSH configuration disabled, host-key checking forced to `yes`, DNS host-key trust disabled, host-key updates disabled, and only the standard user/system `known_hosts` files selected. The user file is passed as an explicit absolute `$HOME/.ssh/known_hosts` path derived from the HOME of the Git execution environment (not OpenSSH's `~` expansion); if that HOME is missing or unsafe to represent, SSH fails closed. It does not read SSH identity files: `IdentityFile=none` leaves authentication to the exact `SSH_AUTH_SOCK` supplied by the environment, and the existing path-scoped session prompt is the only way to grant that socket. A missing SOCKS proxy fails closed. Host keys must already be trusted; the transport neither accepts new keys nor modifies known-hosts files. A `known_hosts` file under a denied path must be explicitly approved by the existing narrow read policy/prompt; no `.ssh` directory or private-key access is added.
