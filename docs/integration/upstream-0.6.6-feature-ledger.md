# Upstream 0.6.6 integration feature ledger and test map

- **Proposal:** [`proposal-integrate-upstream-0.6.6.md`](../proposals/proposal-integrate-upstream-0.6.6.md)
- **Slice:** 1 — feature ledger and test map
- **Baseline inspected:** downstream `main` at `1c50dc9`; downstream `origin/main` at `757f058`; `upstream/main` at `d76ad64` (pi-sandbox 0.6.6)
- **Status:** implementation-ready map; no product or security decision is implied by a `defer` or `reject` disposition

This ledger is the parity checklist for the later upstream-first migration. It records the intended behaviour at the integration boundary, rather than treating an entire file or upstream commit as authoritative. Existing coverage is marked separately from required coverage so that passing upstream tests cannot be mistaken for downstream parity.

The inspected refs were already present locally. This slice did not fetch, switch branches, merge, rebase, reset, or push.

## Dispositions and seams

| Disposition | Meaning in this ledger |
| --- | --- |
| **retain** | Keep the downstream behaviour or the upstream behaviour where it is compatible; port it without weakening its boundary. |
| **adapt** | Keep the intent, but change implementation, types, persistence, or precedence to fit the downstream contract. |
| **replace** | The named upstream/downstream implementation is not the target; use the explicitly stated implementation at the seam instead. |
| **defer** | Record the behaviour and its test gate, but do not make it part of the initial accepted migration without the stated review. |
| **reject** | Do not add the capability in this migration because it would violate the stated security or scope boundary. |

Every row has one primary narrow seam. The seam names are deliberately stable even if their concrete TypeScript interfaces change:

| Code | Narrow integration seam | Contract owner |
| --- | --- | --- |
| **EP** | Effective-policy resolution: composed configuration, canonical matching, precedence, and derived allowances shared by direct tools and the runtime. | `src/config.ts`, `src/policy.ts`, and downstream policy adapters |
| **PP** | Permission-prompt results: an accepted, validated rule plus scope, or an abort; no persistence occurs for an abort or timeout. | `src/ui.ts` with `src/extension.ts` orchestration |
| **CP** | Sanctioned configuration persistence: the sole path for approved `/sandbox` and prompt writes, with protected paths and scope-aware representation. | downstream-owned `src/sandbox-command.ts` and config writer adapter |
| **RD** | Runtime diagnostic events: structured violations, retries, final outcomes, and lifecycle events passed out of sandbox execution. | downstream-owned `src/diagnostics.ts` and `src/status.ts` adapter |
| **PF** | Command preflight hooks: direct-tool, Bash, `!cmd`, Git, SSH-agent, and config-file mutation checks before execution. | `src/extension.ts` plus downstream Git/SSH adapters |
